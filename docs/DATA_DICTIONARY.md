# Dataset and metric definitions

All data is generated by `src/generate_data.py`, seed 42. All carrier names and operational outcomes are fictional. Port names and approximate coordinates are illustrative. Route distances, transit durations and costs are invented, not navigational estimates. Times are stored as UTC without timezone suffixes. Currency is USD. Snapshot: **2026-01-01 00:00:00 UTC**. Dispatches cover 2024–2025.

## Raw source files

| File | Grain | Expected default rows |
|---|---|---:|
| carriers.csv | One fictional carrier | 6 |
| ports.csv | One illustrative port | 8 |
| routes.csv | One directed origin/destination pair | 24 |
| shipments.csv | One input shipment record, including intentional invalid records | 20,100 |
| shipment_events.csv | One shipment event | Approximately 79,000 |

The generator makes 20,000 legitimate shipments, then appends 100 bad records: 20 duplicate IDs, 20 negative weights, 20 unknown carriers, 20 promises before dispatch, and 20 deliveries before dispatch. ETL quarantines these rows; it does not invent replacement values. The first duplicate occurrence wins. If that first row is invalid, a later duplicate is also rejected for manual review.

`manifest.json` records seed, row counts and SHA-256 hashes. CSVs are UTF-8 with comma delimiters and headers. Missing actual delivery dates are blank. Re-running the generator with the same seed, size, and dependency versions produces identical data.

## Shipment columns

| Column | Type | Meaning |
|---|---|---|
| shipment_id | Text PK | SHP-prefixed unique shipment key |
| carrier_id | Integer FK | Carrier assigned at dispatch |
| route_id | Integer FK | Route assigned at dispatch |
| service_level | Text | Standard or Priority |
| weight_kg | Decimal | Positive shipment weight in kilograms |
| shipping_cost_usd | Decimal | Synthetic quoted transport cost; no accounting recognition implied |
| dispatch_at | Timestamp | Actual dispatch time |
| promised_delivery_at | Timestamp | Delivery commitment known at dispatch |
| actual_delivery_at | Nullable timestamp | Completed delivery time, hidden if still in transit or cancelled |
| status | Text | Delivered, In Transit, Cancelled |

Cancelled means an operational cancellation after dispatch in this simulation. Do not equate these records with pre-dispatch order cancellations. The generator uses a latent delivery time to create status at the snapshot; that latent time is not exported for undelivered shipments.

## Dimension and event columns

- Carriers: carrier_id (PK), carrier_name (fictional text).
- Ports: port_id (PK), port_name, country, latitude and longitude (decimal degrees).
- Routes: route_id (PK), origin_port_id and destination_port_id (ports FKs), distance_km (positive synthetic kilometers).
- Events: event_id (PK), shipment_id (FK), event_type (Dispatched, Port Arrived, Port Departed, Delivered, Cancelled), event_at (UTC timestamp), port_id (FK).
- The simplified generator has one destination-port visit per shipment, no transshipment loops. Dwell pairs its arrival and departure. Generalizing to repeated visits requires a visit identifier.

## Curated shipment columns

The curated export has one row per validated shipment. It adds carrier_name, distance_km, origin_port_id, destination_port_id, origin_port, destination_port and:

| Column | Definition |
|---|---|
| is_delayed | 1 if delivered after promise, 0 if delivered on/before promise, blank if not delivered |
| delay_hours | max(0, actual minus promise in hours); blank if not delivered |
| transit_hours | actual minus dispatch in hours; blank if not delivered |
| dispatch_date | UTC dispatch calendar date |
| dispatch_month | YYYY-MM dispatch cohort |
| is_overdue_open | 1 if In Transit and promised delivery is before the fixed snapshot, else 0 |

On-time rate = on-time delivered / all delivered. Mean delay includes zero-delay on-time deliveries. Unresolved shipments must not be counted as on-time. Monthly rates use dispatch cohorts, so the most recent incomplete cohorts can be biased.

## Summary and prediction exports

- carrier_performance: delivered_shipments, delayed_shipments, delay_rate, mean_delay_hours, median_transit_hours, p90_delay_hours; delay_rate_ci95_low/high use a 95% Wilson interval.
- route_performance: the same metrics grouped by directed route (without confidence bounds).
- monthly_performance: the same metrics by dispatch_month (without confidence bounds).
- port_dwell: port_id, port_name, completed_port_visits, mean_dwell_hours. Incomplete visits excluded.
- dim_date: date, year, month_number, year_month and quarter. Covers shipment dispatch dates.
- shipment_predictions: shipment_id, model_version, delay_probability (uncalibrated score 0–1), predicted_delayed (0/1), threshold, scored_at (actual UTC execution time). Current model only. Includes validation/test-period shipments and unresolved shipments, excludes cancellations and the training period. These are retrospective dispatch-feature scores, not a historical live scoring log.
- test_predictions: held-out completed shipment IDs, dispatch_at, is_delayed, delay_probability, predicted_delayed.
- model_metrics: model, split (validation/test), threshold, precision, recall, f1, roc_auc and average_precision.

## Scope

This is a local portfolio implementation. Synthetic model scores and simulated carrier comparisons do not establish performance on real logistics data. It has no real-time ingestion service, authentication, distributed processing, or production monitoring.
